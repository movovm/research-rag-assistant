# Redis 开发规范

## 缓存穿透

缓存穿透是指请求查询一个数据库中不存在的数据。由于缓存无法命中，请求会持续落到数据库。团队采用缓存空值、布隆过滤器和参数校验三层防护。空值缓存必须设置较短 TTL，避免无效数据长期占用内存；布隆过滤器用于大规模只读主键集合；参数校验应尽早拦截明显非法的 ID。

## 缓存击穿

缓存击穿发生在热点 Key 过期瞬间，大量并发请求同时访问数据库。优先使用逻辑过期保证热点数据可用，由后台线程异步重建缓存；对一致性要求较高的场景可以使用互斥锁，并为锁设置超时时间和双重检查。

## 数据一致性

更新业务数据时采用先更新数据库、再删除缓存的 Cache Aside 策略。缓存删除失败时写入消息队列进行补偿重试，并使用 TTL 作为最终兜底。禁止在数据库事务提交前删除缓存，避免回滚后出现脏缓存。
