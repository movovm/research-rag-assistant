# 新人开发手册

## 分支与评审

每个需求从主分支创建 feature 分支。提交评审前必须完成单元测试、接口自测和敏感信息检查。通过 git diff 生成本次变更范围，AI Code Review 只检查差异代码，并按 Critical、Warning、Info 三个级别输出。AI 评审不能代替人工评审，业务逻辑、需求理解和架构取舍仍由开发者负责。

## 单元测试

新增核心业务逻辑需要覆盖正常路径、边界条件和异常分支。JUnit 5 用于测试框架，Mockito 隔离外部依赖。生成式 AI 可以补充测试草稿，但开发者必须运行测试、核对断言意义并检查 Mock 交互，禁止只追求覆盖率数字。

## 敏感配置

API Key、数据库密码、Token 和个人路径不得提交到 Git。配置文件只引用环境变量，仓库提供 application-example.yml 说明所需字段。提交前使用 git diff 和密钥扫描再次检查。
